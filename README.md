# Streamstats - потоковый анализатор файлов

Лабораторная работа №2 по предмету "Программирование на Python". Программа представляет собой пакет утилит командной строки (CLI)

## Что делает программа

- **Потоковый анализ** - обрабатывает входные файлы построчно, не загружая их целиком в оперативную память, что позволяет анализировать гигабайтные логи со стабильным и минимальным потреблением RAM.
- **Агрегация данных** — объединяет статистику из нескольких файлов за один запуск, подсчитывая общие метрики, распределение событий по уровням логов и источникам.
- **Два режима обработки ошибок** — прекращает выполнение при первой некорректной строке или пропускает её с логированием предупреждения.

## Использование

### Основной запуск (Анализ файлов)

```bash
# Анализ одного или нескольких JSONL файлов с выводом отчета в JSON
python -m streamstats analyze "json файлы/test.jsonl" --format jsonl --output "json отчёты/report.json"

# Анализ CSV файлов
python -m streamstats analyze "csv файлы/test.csv" --format csv --output report.csv
```

### Режим пропуска поврежденных строк (`--skip-invalid`)

```bash
# Пропускать битые строки, записывать WARNING в stderr и сохранять их количество в отчет
python -m streamstats analyze test.jsonl --format jsonl --output report.json --skip-invalid
```

### Генерация отчета в формате CSV (Дополнительное задание)

```bash
# Если путь выходного файла заканчивается на .csv, отчет сформируется в плоском табличном виде
python -m streamstats analyze input.jsonl --format jsonl --output report.csv
```

### Измерение потребления памяти (Дополнительное задание)

Для проверки эффективности потоковой обработки был проведен замер потребления оперативной памяти (RAM) при анализе лог-файла большого объема.

* **Размер входного файла:** 642 МБ
* **Пиковое потребление памяти (Peak RAM):** 0.16 МБ
* **Инструмент замера:** `memory_profiler` / `tracemalloc`

Стабильно низкий показатель RAM (менее 1 МБ) полностью подтверждает, что файлы обрабатываются строго построчно через генераторы и не загружаются в память целиком.

## Что поддерживает

- **Модель лога (ISO 8601):** Строгая валидация полей `timestamp`, `level` (DEBUG, INFO, WARNING, ERROR, CRITICAL), `source` (непустая строка) и `message`.
- **Детерминированный Top-5:** Сортировка источников с наибольшим числом ошибок (`ERROR`/`CRITICAL`) строго по алфавиту при равных значениях счетчиков.
- **Сохранение кодировки:** Полная поддержка кириллицы (UTF-8) во входящих сообщениях и итоговых отчетах.
- **Защита от пустых файлов:** Пустой файл обрабатывается корректно и создает нулевой отчет без падения программы.
